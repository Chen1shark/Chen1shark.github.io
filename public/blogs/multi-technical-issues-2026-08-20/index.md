# 2026-08-20 工作日志：多项技术问题整理

## 今日概览

当天处理两类工作：一是收口某内部系统的延迟生效配置，重新明确未来日期代表“配置生效时间”，修复立即保存、待生效快照和任务应用之间的分支边界；二是对一组相互关联的存量业务模块进行初步调研，形成后续代码走读地图。公开版本只保留通用结论，已移除真实业务名称、组织口径、字段名和内部模块关系。延迟生效配置的关键保存场景已验证，关联模块仍处于静态分析阶段。

## 完成事项

- 明确未来日期描述的是配置生效时间，而不是单一的首次启用动作。
- 区分首次等待生效与已有记录的计划变更两种业务形态。
- 修复部分字段未提交时可能把现有值覆盖为空的问题。
- 收紧任务扫描条件对空值和空字符串的处理。
- 核对关联对象选择组件可复用已有查询能力，无需新增后端接口。
- 梳理计划记录、结果核算、主动申报和现场位置等模块的职责边界。
- 恢复联调结束后应关闭的临时调试入口。

## 问题与解决

### 不同业务形态误用同一保存分支

- **现象**：处于停用状态的记录提交未来日期时，部分配置被立即修改，没有按预期延后生效。
- **分析**：仅根据当前启停状态选择分支，会把“首次等待生效”和“已有记录的计划变更”混为一类。未来日期的业务含义是配置生效时间，不能由单一布尔字段推断。
- **处理**：结合当前状态、计划日期和是否存在待生效快照判断记录形态；只有首次等待生效走即时维护分支，其他未来变更写入快照。
- **验证**：两条关键保存路径已验证，更多组合场景仍需补充测试。

### 部分更新把未提交字段写成空值

- **现象**：带未来日期的请求正常，不带日期的部分字段更新却可能返回异常或丢失现有值。
- **分析**：立即保存需要更新完整实体，而请求只提交了部分字段；若直接映射，未传字段可能被解释为空值。
- **处理**：在写入当前数据或生成快照前，用现有值补齐未提交字段，并显式区分“不修改”和“清空”。
- **验证**：常用的立即保存和计划保存路径已验证；完整的部分字段组合仍待覆盖。

### 调度成功但记录没有发生变化

- **现象**：调度平台显示任务执行成功，目标记录仍保持原状态。
- **分析**：任务成功只说明处理器没有抛出异常，不代表扫描条件命中了记录。空字符串形式的快照、尚未到期的日期或状态不匹配都会造成跳过。
- **处理**：统一把空值和空字符串识别为“无快照”，并在解析前排除无效内容；测试时同时核对扫描条件和任务日志。
- **验证**：扫描逻辑已调整，实际到期应用仍需结合计划日期验证。

### 无法仅从主配置判断运行环境

- **现象**：主配置文件没有直接声明当前运行环境，无法判断实例连接的是哪套基础设施。
- **分析**：实际环境通常由启动参数、配置来源和运行时覆盖共同决定，业务字段中的地域或站点标识也不等于部署环境。
- **处理**：从启动日志、进程参数和实际依赖地址三处交叉确认，不根据单个配置文件下结论。
- **验证**：方法已整理，真实实例仍需结合一次运行现场确认。

## 技术记录

延迟生效配置的保存逻辑可以抽象为：

```text
若提交未来生效日期，且记录不是首次等待生效：
  保存计划日期和待生效快照
  保持当前数据不变
否则：
  立即更新当前数据
  按业务规则清理未应用草稿
```

任务处理顺序应先应用到期快照并清理计划字段，再处理首次生效记录。若顺序相反或应用后保留旧计划字段，同一条记录可能在一轮任务中被重复处理。

关联模块可先按以下边界理解：

```text
计划记录：承载对象、日期与占用规则
结果核算：根据计划与实际记录计算时长
主动申报：按业务项目提交独立申报数据
现场位置：提供实时位置信息，不直接等同于到岗核验
```

这些结论仅用于建立代码走读地图，具体字段、接口和任务节奏仍应以源码和实际运行结果为准。
