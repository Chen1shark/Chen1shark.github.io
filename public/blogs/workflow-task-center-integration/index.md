## 问题与解决

### 单人任务提示不属于当前用户

- **现象**：业务侧已确认当前用户是任务处理人，但流程服务仍拒绝办理。
- **分析**：流程变量中的处理人使用数值类型，办理接口传入的是字符串。若服务端直接进行对象相等比较，数值和字符串即使内容相同也不会相等。
- **处理**：在创建或改派单人任务时，将用户标识统一转换为字符串后再注入流程变量。
- **验证**：类型链路已静态核对；新流程实例的实际办理结果待验证。

### 远程流程失败后本地状态仍可能提交

- **现象**：撤回逻辑捕获远程异常后仅记录日志，调用方无法感知失败。
- **分析**：吞掉异常会使本地事务继续提交，造成业务状态与流程实例状态不一致。
- **处理**：保留异常并向上抛出，让事务按既定规则回滚；后续仍需评估跨服务调用失败时的补偿机制。
- **验证**：异常传播路径已检查，故障注入测试待完成。

### 待办列表出现归属存疑的数据

- **现象**：测试账号看到的部分待办与预期身份不一致。
- **分析**：共享候选任务、单人指派任务和管理视图的可见范围不同；使用高权限账号无法准确验证普通用户的待办归属。
- **处理**：将测试拆分为普通无关用户、候选用户、指定处理人和管理用户四类账号场景。
- **验证**：测试方案已整理，真实角色数据下的结果待确认。

### 代码生成产物偶发读取失败

- **现象**：增量编译时提示某个自动生成的映射实现文件不存在，随后又能在输出目录看到该文件。
- **分析**：可能是注解处理器生成时机与 IDE 增量索引之间的竞态，且问题文件与本次业务修改没有直接关系。
- **处理**：优先执行干净构建；必要时清理 IDE 缓存并重新生成注解处理产物。
- **验证**：待在完整构建环境复现和确认。

## 技术记录

单人任务的处理人标识应在系统边界处统一类型：

```java
Map<String, Object> variables = Map.of(
        "handlerUserId", String.valueOf(handlerUserId)
);
workflowClient.complete(currentUserId, instanceId, variables);
```

任务中心常见的两条数据链路：

```text
状态通知：业务状态变化 -> 异步消息 -> 任务中心登记待办或办结
待办查询：当前用户 + 流程定义 + 过滤条件 -> 查询运行中的任务
```

流程候选人通常在实例启动时形成快照，因此修改配置后不一定会影响已经运行的流程实例。
