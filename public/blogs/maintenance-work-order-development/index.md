## 问题与解决

### 故障现象表的设备类型字段取值错误

- **现象**：初始化故障现象数据时，设备类型字段填入了板卡类型字典的目录编码，界面展示异常。
- **分析**：该字段在既有业务中存的是"设备类型字典"的取值（格式为目录前缀+编码，如 `equip_type_xxx`），代码在展示/导入/筛选时都通过字典的 `val` 反查名称。填成字典目录编码既不是合法取值，也无法反查，导致 label 为空、导入校验失败、筛选不到。同时业务上板卡故障现象为多类板卡共用，不应归属单一板卡类型。
- **处理**：与产品确认后，将故障现象按板卡类型展开为组合数据，设备类型字段存板卡类型字典的合法 `val`；新增时按类型/图片规则解析。
- **验证**：SQL 数据调整为组合记录后，字典反查与展示正常（已验证字典取值格式；组合数据展示结果待联调确认）。

### 接口路径与项目惯例不一致

- **现象**：详情接口先写为 `/{id}/detail`，后被指正；下载接口在 `/download/{id}` 与 `/{id}/download` 间摇摆。
- **分析**：以项目既有代码为准而非个人偏好——详情主流写法为 `/detail/{id}`，下载为 `/download/{id}`，按父 id 查子列表为 `/list/{父id}`，`/{id}/items` 无先例。
- **处理**：详情改为 `/detail/{id}`，下载改为 `/download/{id}`，模板工序明细改为 `/list/{templateId}`。
- **验证**：路径与项目惯例一致（待重新编译验证）。

### 模板下载文件名错误且中文乱码

- **现象**：下载得到的文件名不是上传时的名称，且中文显示为乱码。
- **分析**：下载名误用了文件服务返回的 `downName`，其来源是磁盘文件名而非上传原名，且内部存在字符集转换易乱码；同时 Content-Disposition 仅用 `filename` 时，中文经 URL 编码后浏览器无法正确解码。
- **处理**：下载名改用上传时存入模板表的名称 + 扩展名；响应头改用 RFC 5987 的 `filename*=UTF-8''` 格式。
- **验证**：已修复实现，待重新编译后验证文件名与中文显示。

### URLEncoder 受检异常导致编译错误

- **现象**：编译报错"必须对其进行捕获或声明以便抛出"。
- **分析**：`URLEncoder.encode(String, String)` 声明抛出 `UnsupportedEncodingException`，下载方法未处理。
- **处理**：将文件名字符串编码逻辑抽成私有方法，内部 try-catch 记录日志并抛出业务异常。
- **验证**：已修复实现，待重新编译验证。

### 分页默认排序与返回结构不规范

- **现象**：模板列表分页返回了实体对象（暴露内部字段），且默认排序语义需确认。
- **分析**：项目惯例为列表返回 PageData、明细返回 VO；分页基类默认按更新时间排序，列表型业务按创建时间更直观。
- **处理**：新增模板列表 PageData 与工序明细 VO；两个查询上下文覆盖默认排序为按创建时间倒序；模板分页入参精简为仅 `page`/`size`。
- **验证**：已修复实现，待重新编译验证。
