## 问题与解决

### 字典值与业务字段语义不一致

- **现象**：初始化数据使用了字典目录标识，而业务字段实际需要保存字典项值，导致展示和筛选异常。
- **分析**：字典目录、字典项和值对象承担不同职责，不能仅凭字符串相似就混用。
- **处理**：按业务字段约定保存稳定的字典项值，并在写入前完成合法性校验。
- **验证**：使用通用测试数据验证名称回显、导入校验和筛选条件可以使用同一套映射规则。

### 接口风格不统一

- **现象**：详情、下载和子资源查询最初采用了不同的路径表达方式。
- **分析**：同一项目中的接口应遵循一致的资源命名和返回结构，减少调用方理解成本。
- **处理**：按照现有公共约定统一接口风格；公开文章不保留真实路径。
- **验证**：对照同类资源检查命名、请求方式和响应模型的一致性。

### 下载文件名错误及中文乱码

- **现象**：下载名称没有使用上传原名，中文文件名在部分浏览器中显示异常。
- **分析**：存储层文件名不等于业务展示名；仅使用传统 `filename` 参数无法稳定表达 UTF-8 文件名。
- **处理**：下载名称取业务侧保存的原始名称，并使用 RFC 5987 的 `filename*` 参数编码。
- **验证**：使用中英文和包含空格的文件名进行下载测试，名称可以正确还原。

### 列表返回模型暴露内部字段

- **现象**：分页列表直接返回持久化对象，包含列表页不需要的信息。
- **分析**：持久化模型、列表模型和详情模型的职责不同，直接复用会增加耦合并扩大数据暴露范围。
- **处理**：为列表和详情分别定义最小响应模型，并显式映射需要的字段。
- **验证**：检查接口响应，只保留页面展示所需的信息。

## 技术记录

### 模板上传的一般流程

```text
校验文件
  → 保存原文件并取得引用
  → 解析模板条目
  → 校验必填项与枚举值
  → 保存模板和明细
```

### UTF-8 下载文件名

```java
String encodedName = URLEncoder.encode(fileName, StandardCharsets.UTF_8)
    .replace("+", "%20");
response.setHeader(
    "Content-Disposition",
    "attachment; filename*=UTF-8''" + encodedName
);
```

### 响应模型原则

- 列表响应只包含筛选和展示需要的字段。
- 详情响应按业务场景补充关联信息。
- 审计字段、内部标识和权限信息默认不对外返回。
