## 问题与解决

### 依赖缺少源码

- **现象**：部分依赖只有编译产物，无法直接查看实现。
- **分析**：缺少源码包时，反编译可能违反项目约定，也容易把推断当成事实。
- **处理**：只根据公开接口、导入关系和调用结果判断职责；无法确认的实现细节明确标记为待确认。
- **验证**：可以说明调用边界和输入输出，但不在公开文章中保留依赖名称、仓库地址或内部类关系。

### 从站返回 Illegal Function

- **现象**：主站使用 FC04 读取输入寄存器时，从站返回异常功能码。
- **分析**：异常响应的功能码等于请求功能码加 `0x80`，后续异常码表示从站不支持当前功能。
- **处理**：将模拟从站的数据区配置为 Input Register，并确认主从两端使用相同功能码。
- **验证**：功能码异常消失，请求进入地址范围检查阶段。

### 从站返回 Illegal Data Address

- **现象**：功能码一致后，读取仍返回地址异常。
- **分析**：模拟从站没有配置主站请求的寄存器范围。
- **处理**：根据测试用例创建覆盖请求范围的输入寄存器窗口，并使用非业务数据填充。
- **验证**：主站可以读取寄存器，采集流程进入解析阶段。

### 读取成功但数据被判定为无效

- **现象**：寄存器读取成功，但应用侧认为数据没有变化或全部无效。
- **分析**：标志位没有触发目标数据块，或者模拟数据全部为零，被有效性检查过滤。
- **处理**：仅打开一个测试标志位，并为对应数据块填入可识别的模拟值，减少无关请求。
- **验证**：目标数据块被读取并进入后续处理。

## 技术记录

### Modbus TCP FC04 帧结构

请求帧由 MBAP 头和 PDU 组成：

```text
事务标识 | 协议标识 | 长度 | 单元标识 || 功能码 | 起始地址 | 数量
```

异常响应规则：

| 异常码 | 含义 |
|---|---|
| `01` | Illegal Function，功能码不支持 |
| `02` | Illegal Data Address，地址范围不可用 |
| `03` | Illegal Data Value，请求参数不合法 |

### 标志位与数据块

```text
读取配置
  → FC04 读取标志位寄存器
  → 拆分每个寄存器的 bit
  → 对值为 1 的标志读取对应数据块
  → 校验、去重并输出采集结果
```

- 配置描述“去哪里读”，设备寄存器保存“读到什么”。
- 一个 16 位寄存器最多可以表达 16 个布尔标志。
- 标志位和值寄存器应分别使用独立、可验证的模拟数据。

### 一致性哈希的通用用途

- 以稳定设备标识作为数据键。
- 通过哈希环为多个采集节点分配任务。
- 成员变化时只迁移部分键，减少大规模重新分配。
- 公开文档只描述算法，不记录真实节点、地址和协调组件。
