## 问题与解决

### 公司内部 jar 无源码，无法直接查看实现

- **现象**：项目依赖的公司内部 jar（Modbus 通信库、一致性哈希库等）只有编译产物，IDE 无法查看源码。
- **分析**：检查本地 `.m2` 仓库，确认无 `*sources*.jar`；这些 jar 来自公司私有 Nexus 仓库。按约定不反编译。
- **处理**：通过 PSD 源码中的 `import` 和方法调用，反推每个 jar 提供的类与用途；确切归属（如事件类属于哪个 jar）无法从源码 100% 确认，标记待核对。
- **验证**：基于 import 统计整理出 PSD 用到的公司 jar 清单及"代码→jar"调用关系图。需源码时向组长申请对应内部分析工程。

### 本地测试采集，Modbus Slave 返回异常 84 01（Illegal Function）

- **现象**：PSD 读取标志位寄存器时，slave 回 `84 01`。
- **分析**：PSD 使用 FC04（读输入寄存器），而 Modbus Slave 默认只配了保持寄存器（FC03），不支持 FC04。`84` = `04 + 0x80` 表示异常响应，后随的 `01` 才是原因（非法功能）。
- **处理**：在 Modbus Slave 的 Slave Definition 中把 Function 改为 `04 Input Register`。
- **验证**：异常码从 `01` 变为 `02`，说明 FC04 已被支持。

### 异常码变为 84 02（Illegal Data Address）

- **现象**：FC04 支持后，读地址 32006 仍回 `84 02`。
- **分析**：slave 在该地址没有数据；PSD 请求的地址范围未在 slave 中配置。
- **处理**：在 Modbus Slave 新建 Input Register 窗口，Address=`32006`、Quantity=`12`，填入非 0 值。
- **验证**：标志位读取成功，PSD 进入读曲线数据阶段。

### 读曲线数据报 84 02 与"原始数据全为0"

- **现象**：标志位读通后读 42220 又 `84 02`；建好窗口后读到了，却报"原始数据全为0"。
- **分析**：第一次是 42220 数据窗口未建；第二次是窗口建了但 110 格填的是 0，被全 0 检查丢弃。另外标志位全填非 0 会触发全部 160 条曲线，导致一堆地址报错。
- **处理**：Modbus Slave 开两个窗口并存——窗口1（标志位）Address=`32006` Quantity=`12`，仅地址 `32008` 填 `1`、其余填 `0`；窗口2（曲线数据）Address=`42220` Quantity=`110`，全填非 0。
- **验证**：PSD 日志出现"曲线数据入库"，曲线采集链路跑通。

## 技术记录

### Modbus TCP FC04 帧结构

请求帧 = MBAP 头（7 字节）+ PDU（功能码+地址+数量）：

```text
事务ID(2) | 协议ID(2,固定0000) | 长度(2) | 单元ID(1) || 功能码(1) | 起始地址(2) | 数量(2)
```

读标志位请求示例（地址 32006、数量 12）：

```text
00 01 00 00 00 06 16 04 7D 06 00 0C
```

正常响应：功能码原样回 `04` + 字节数 + 数据。`18` 是字节数（0x18=24），不是寄存器值；真正的寄存器值在其后，每个寄存器 2 字节（16 bit）。

异常响应：功能码 = `请求FC + 0x80`（FC04 变 `84`）+ 异常码：

| 返回 | 异常码 | 含义 |
|---|---|---|
| `84 01` | Illegal Function | slave 不支持该功能码 |
| `84 02` | Illegal Data Address | 该地址没数据 |
| `84 03` | Illegal Data Value | 数据值非法 |

### 标志位（update_bits）与 bit 机制

- 数据库存的是配置/地址（"去哪读"），Modbus 设备存的是实际数值（读到的数）。
- `update_bits` 格式 `寄存器号.位号`，如 `32008.00` = 寄存器 32008 的第 0 位。位号是十进制（0~15），不是十六进制。
- 1 个 bit = 1 条曲线的"有没有新数据"开关；1 个寄存器 16 bit = 最多 16 条曲线。
- PSD 读回整个寄存器值后，遍历 16 位、拼成 `"32008.0x"` 去数据库查对应曲线；位=1 表示该曲线有更新。
- bit 的位置来自数据库，bit 的值来自 Modbus。

### PSD 曲线采集三阶段

```text
阶段0 查数据库:  查曲线配置表，拿到 160 条曲线（update_bits + start_register + datas_length=110）
阶段1 读标志位:  FC04 读 32006~32017（12 个寄存器），拆 16 bit，看哪条曲线有更新
阶段2 读曲线数据: 对位=1 的曲线，FC04 读其 start_register 起 110 个寄存器，全0检查→去重→上报
```

### 一致性哈希分片

- 对"设备 ip:port"哈希，决定该设备归哪个采集节点采，避免多实例重复采集。
- 不存"设备→节点"映射表，靠哈希确定性每次实时算；内存里维护节点环，节点列表放共享存储。
- 单实例环境恒为"本节点负责"，该机制不生效。
